# dsh-visual-canvas

DSH 可视化前端编辑插件：**在浏览器里点选 / 拖拽 / 缩放 / 改样式，改动直接写回你的源码**，并且 DSH 的 Agent 能在同一个会话里看见并接着改。

一句话定位：**给 DSH 装一块「看得见的前端画布」**，不挑框架，不引入构建依赖。

---

## 它解决什么

改一个按钮的颜色，正常流程是：打开编辑器 → 找到组件 → 找到那一行 → 改 → 存 → 切回浏览器刷新。
有了画布就是：**在页面上点它 → 拖一下 / 改个色 → 源码已经变了**（HMR 自动刷新）。

和现成工具的区别（详见 `DESIGN.md` 的调研）：

| | 现成工具 | 本插件 |
|---|---|---|
| 技术栈 | 多数绑定 React / Next / Tailwind | **代理注入，任意栈都能跑** |
| Agent 协作 | 基本没有，或要装外部 CLI | **直接用 DSH 自己的 Agent**（`canvas_*` 工具） |
| 依赖 | 通常要装一堆包 | **零运行时依赖**（只用 Node 内置模块） |
| 改动语义 | 有的只是「导出代码」 | **最小补丁写回真实源文件 + 快照可撤销** |

## 快速开始（克隆即用）

**前置**：DSH `>= 0.2.0-rc.1`、Node `>= 18`。插件**零运行时依赖**，只用 Node 内置模块，不用 `npm install`。

```sh
# 1) 克隆
git clone https://github.com/Lzdlh1/dsh-visual-canvas.git
cd dsh-visual-canvas

# 2) 先把自带的 demo 跑起来 —— 零依赖，一条命令就有一个"真实前端项目"
node demo/server.mjs 5173
```

**另开一个终端**，把 `cordis.patch.yml` 里的两项改成你自己的：

```yaml
config:
  target: "http://127.0.0.1:5173"        # 你的 dev server（跑 demo 就保持默认）
  projectRoot: "D:/path/to/dsh-visual-canvas/demo"   # ★ 必填：源码根目录的绝对路径
```

> `projectRoot` **留空插件不会激活** —— 这是故意的：猜错了它会去改不相干的仓库。

```sh
# 3) 装进 profile（link: 后面是克隆下来的绝对路径）
dsh plugin --profile desktop add link:/absolute/path/to/dsh-visual-canvas

# 4) 重启 DSH
```

**打开 `http://127.0.0.1:19387/canvas/`** —— 应该看到一块无限画布。

### 怎么确认真的装上了

```sh
curl http://127.0.0.1:19387/canvas/__canvas__/status
```

返回里 `active: true` 且 `projectRoot` 是你填的路径，就对了。`active: false` 时看 `reason`，最常见的就是 `projectRoot` 没填或路径不存在。

### 接下来试什么

1. 画布左上角 **`＋ 添加画板`**，路径填 `/`（demo 的首页）→ 页面的实时预览就出现了
2. 在画板里**点任意元素** → 右上角属性面板出现 → 改个颜色 / 拖一下 → **`demo/` 里的源文件已经变了**
3. 底部指令条写一句话（比如"把主按钮改成圆角 12px"）→ 发给 DSH Agent，它会带着**你刚选中的元素位置**去改

## 自带技能：`visual-canvas-demo-first`

仓库里的 `skills/visual-canvas-demo-first/` 是一个 **DSH 技能**：
**开发任何前端界面之前，先用画布做出可点的 demo，确认之后再写正式代码。**

装上它（复制到 DSH 的技能根）：

```sh
cp -r skills/visual-canvas-demo-first "$DSH_HOME/skills/"
```

之后 Agent 在遇到"做一个页面 / 组件 / 后台 / 落地页"这类任务时会**自动启用**它，
流程变成：**搭个最小 HTML → 挂进画布 → 在画布里调 → 拿给你看 → 你确认 → 才写正式代码**。

> **为什么值这一条规则**：界面是**看**出来的，不是描述出来的。
> 写完 800 行才发现理解偏了，返工最贵；而花十分钟先让它可见，偏差当场就能发现。

⚠️ DSH 的技能目录**按会话开始时快照** —— 新装的技能**本次会话用不到**，**新开一个会话才生效**。

## 安装

```sh
# 把 <克隆下来的绝对路径> 换成你自己的；--profile 换成你的 profile 名
dsh plugin --profile desktop add link:<克隆下来的绝对路径>
```

> ⚠️ **必须是绝对路径**，而且 `link:` 后面**不要加引号**。
> 装完**重启 DSH** —— 插件在启动时加载，热装不会生效。

然后重启 DSH。侧边栏不需要新面板——它挂在**现有的 Web 服务器**上，不额外开端口。

## 配置

写在 profile 的 `cordis.patch.yml`：

```yaml
- insert:
    - id: visual-canvas
      name: dsh-visual-canvas          # 必须是**包名**（由 profile 的 node_modules 解析）
      config:
        target: "http://127.0.0.1:5173"   # 你的前端 dev server
        projectRoot: "D:/my-app"          # 源码根（**必填**，否则不知道去哪找源码）
        prefix: "/canvas"                 # 访问路径前缀
        standalonePort: 19390             # 独立端口（见下：侧边栏必须用它）
        autoApply: true                   # true 直接落盘；false 只预览待确认
        gitCheckpoints: true              # 每次落盘建一个 [canvas] 提交（可选）
        snapshotRoot: ""                  # 撤销快照目录；留空 = $DSH_HOME/visual-canvas/snapshots
```

## 两个地址：为什么必须有独立端口

插件同时提供**两个入口**，内容完全一样：

| 地址 | 用途 | 能用吗 |
|---|---|---|
| `http://127.0.0.1:19390/canvas/` | **推荐**；侧边栏、普通浏览器 | ✅ |
| `http://127.0.0.1:19387/canvas/` | DSH 端口下，不额外占端口 | 普通浏览器 ✅ / **侧边栏 ❌** |

**为什么侧边栏打不开 DSH 端口下那个**：DSH 侧边栏的嵌入浏览器有一段地址校验，
**拒绝打开与 DSH 应用自身同源的地址**（`parseBrowserAddress` 里的 `application-origin` 判定，
提示语是「不能在嵌入浏览器中打开 DSH 应用自身」）。而 DSH 的界面就跑在
`http://127.0.0.1:19387`，画布挂在同端口的 `/canvas/` 下——**同源**，于是必然白屏。

同源判定包含端口，所以换个端口就是换个 origin。这就是 `standalonePort` 存在的原因：
它用 Node 内置 http 起一个只在回环上监听的小服务器，复用**完全相同**的代理、
覆盖层、访问控制与 WebSocket 逻辑（`lib/standalone.js`）。

> 实测依据：面板能正常打开 `http://127.0.0.1:5173/`（演示站点，不同 origin），
> 打不开 `http://127.0.0.1:19387/canvas/`（与 DSH 同 origin）。

配好之后：

1. 跑起你的前端项目（`npm run dev`）
2. 打开 **`http://127.0.0.1:19390/canvas/`**（或在 DSH 侧边栏里输这个地址）
3. 右下角出现画布面板，点页面元素即可编辑

实际地址会写在插件日志与 `/canvas/__canvas__/status` 接口的 `urls` 字段里
（`standalonePort: 0` 时端口由系统分配，只能从这两处查）。

## 无限画布（主入口）

打开 `<前缀>/`（即 `http://127.0.0.1:19390/canvas/`）看到的是**无限画布**，
不是单个页面。画布上可以摆多块**画板**，每块画板是应用里某个路由的实时预览。

| 操作 | 效果 |
|---|---|
| 滚轮 | 以指针为锚点缩放 |
| 拖空白处 | 平移画布 |
| `0` / `1` | 缩放到适应 / 回到 100% |
| 拖画板标题 | 移动画板 |
| 拖画板右下角 | 改尺寸 |
| `Delete` | 删除选中的画板 |
| ＋ 添加画板 | 输入应用内路径（如 `/login`），选设备，加一块画板 |

**画板里的 iframe 始终按设备真实尺寸渲染**（1440×900 就是 1440×900 CSS 像素），
缩放只影响观看。这是刻意的：否则在 12% 缩放下，页面的媒体查询会按 173px 宽度生效，
你看到的布局根本不是真实布局。

### 布局文件：`.dsh-canvas/workspaces.json`

画板列表与位置**存在你的项目里**，跟着 git 走，团队共享——别人 clone 项目、
装了同款插件，打开画布看到的是同一块画布，可以直接接着编辑。

```jsonc
{
  "version": 1,
  "workspaces": [
    {
      "id": "login",
      "name": "登录页",
      "path": "/login",
      "device": "desktop",
      "rect": { "x": 0, "y": 0, "w": 1440, "h": 900 },
      "spec": "登录页要突出第三方登录入口"
    }
  ]
}
```

为「可合并」做的五件事（每一条都是为 git 服务的）：

1. **稳定键序**（id → name → path → device → rect → spec）：否则同一份内容在不同机器上序列化出不同文本，diff 全是噪声
2. **不写时间戳 / 机器信息 / 绝对路径**：`path` 只存应用内路由
3. **统一 LF + 结尾换行**
4. **保留未知字段**：旧版本插件不会抹掉新版本写的字段
5. **写入前冲突检测**：文件在读取后被外部改过就拒绝写入，让你先决定

`spec` 字段是为「规格跟着界面走」准备的——需求描述和它描述的那个界面存在一起，
而不是散在聊天记录里。

**视口状态（缩放/平移）不在这里**：那是每个人自己的，存在 `$DSH_HOME/visual-canvas/views/` 下。

### 左侧工作区列表

画布左边是一份工作区清单，**按路径分组**——同一个路由在手机/平板/桌面各开一块画板时，
它们自然落在同一组里，这就是「同路径多设备对比」。

| 元素 | 作用 |
|---|---|
| 搜索框 | 匹配名称、路径、**规格**、设备名（含中文标签）。搜不到时明确提示，而不是留白 |
| 组头路径 | 显示这一组是哪个路由 |
| 组头「+设备」 | 用同一路径再开一块画板（对话框预填路径，焦点直接落在设备上） |
| 列表项 | 点一下 = 选中并**把画布居中到它**（在视野外时不然会以为没反应） |
| 规格那一行 | **点一下就地编辑**，回车保存 |

规格参与搜索是刻意的：用户常常记得「那个要突出第三方登录的页面」，
而不记得它叫什么名字。而「点一下就能写规格」是**规格沉淀**的入口——
需求描述和它描述的那个界面存在一起，随布局文件一起提交，团队可见。

### 在画板里直接编辑

画布上点「**选择元素**」（或随时按住 `Alt` 点击）后，就能在画板里直接点元素改样式：

| 操作 | 效果 |
|---|---|
| 点「选择元素」 | 进入选择模式；再点一次或按 `Esc` 退出 |
| 在画板里点元素 | 选中，显示高亮框、`标签 · 文件:行` 徽标、右侧样式面板 |
| 面板改样式 | 写回源码；画板靠 HMR 自动刷新 |
| 撤销 / 重做 | 走快照，不影响你其他未提交的编辑 |
| 选父级 / 选子级 | 在层级里上下移动 |

**默认不开选择模式**是刻意的：画板首先是「看你的应用」的地方，
页面自己的点击该正常工作。要编辑就明确开一下。

#### 为什么不做「每个画板注入一份覆盖层」

因为画板与画布外壳**同源**（都由插件在同一端口代理），外壳可以直接往 iframe 的
document 上挂监听、用 `elementFromPoint` 命中元素、读它的 class 与文本。

如果不同源，就只能给每块画板各注入一份覆盖层再靠 `postMessage` 互相喊——
N 个浮动面板、N 条 WebSocket、N 份选中态。同源让这一切变成一个。

坐标换算用 `iframe.getBoundingClientRect().width / iframe.clientWidth` 得到显示缩放比，
而不是直接用画布的 zoom：这样以后加任何变换都不会算错。

> 一个必须记住的坑：**iframe 每次导航都会换成新的 document**（刷新、HMR 重载都算），
> 挂在旧 document 上的监听随之作废。所以判断「挂过没有」要用 document 身份，
> 不能用布尔标记——用布尔标记的话，一次 HMR 之后元素选择就**静默失效**了（我踩过）。

画布底部有一个输入框：**选中一块画板 → 打一句话 → 回车**，指令直接发给 DSH 的 Agent。

它的价值在于**上下文**。用户说「这个按钮太丑了」，模型单独听这句话无法行动；
但画布会把「用户指着的东西」一起打包：

```
【画布上下文】
画板：登录页
应用路径：/login
设备：desktop 1440×900
该画板的规格：登录页要突出第三方登录入口
选中元素：<button> 文本「开始体验」 class=btn btn-primary
源码位置：src/Login.tsx:42（置信度 exact）

用户说：把主按钮改成圆角 12px
```

用户原话**完整保留在最后**，不被改写——模型看到的是「用户说的」+「他指的是什么」。

**我们不自建 LLM 调用。** 走的是 DSH 自己的 `sessionController.prompt`，
也就是「往某个会话投递一条用户消息」。于是画布输入框和聊天框走**同一条路**：
Agent 的工具、上下文、历史完全一致，不需要知道消息是从画布来的。

投递用 `mode: "queue"`：不打断 Agent 正在做的事。

### 画布里的 AI 指令条

#### 指令发给哪个会话

插件本身不属于任何会话，所以按优先级取：

1. **工具调用记下来的会话**——只要 Agent 用过一次 `canvas_*` 工具，就确切知道谁在看画布（`exec.agent.id`）
2. **按项目目录匹配**——`sessionController.list()` 返回的会话都带 `cwd`，挑目录与项目根相同的；多个时优先「正在运行」再取最近活跃
3. 都不行就**明确报错并告诉你怎么办**，绝不猜一个会话把消息投错地方

界面右下角会显示「→ 会话 …xxxx（按项目匹配 / 已绑定）」，鼠标悬停能看到完整会话 id。
不可用时按钮会灰掉**并说明原因与下一步**，而不是让人以为是坏了。

## Agent 协作

插件给 DSH 的 Agent 注册了这些工具，**和人手拖拽共享同一条写回管道**（所以两者不会互相打架）：

| 工具 | 用途 |
|---|---|
| `canvas_status` | 看项目栈、样式方案、待确认改动、撤销深度 |
| `canvas_locate` | 把元素线索定位到源码，返回置信度与候选 |
| `canvas_style` | 对已定位元素应用样式改动 |
| `canvas_undo` / `canvas_redo` | 撤销 / 重做画布改动 |
| `canvas_pending` | 应用或丢弃待确认改动 |

实际用法举例（直接跟 DSH 说）：

> 「看一下画布上我选中的那个卡片在第几行，把它的圆角改成 12px」
> 「把项目里所有 `.card` 的边框颜色统一成 #e5e7eb」

因为 Agent 能看到画布状态，所以**它和你改的是同一份东西**，不需要你复述「我说的是页面上那个蓝色的按钮」。

## 兼容性（如实说明）

「不挑技术栈」是本插件的核心目标，但**定位精度受框架能力约束**，分三档：

| 档 | 手段 | 覆盖 | 精度 |
|---|---|---|---|
| **A** | 编译期注入 `data-*`（计划中） | React / Vue / Svelte | 精确到行 |
| **B** | 运行时读组件内部信息 | React（fiber `_debugSource`）、Vue、Svelte | 精确到行（dev 构建） |
| **C** | 宿主侧按文本 / class 搜源码 | **任意栈**（含纯 HTML、模板引擎） | 到文件+行，需唯一命中 |

C 档是兜底，也是「任意栈都能用」的实现基础：**只要项目能跑，元素上总有可辨识的文本或 class**。

**代理注入这一层是真正与框架无关的**：不管 Vite / Next / Nuxt / SvelteKit / 纯静态 / Django 模板，
只要它吐 HTML，插件就注入 `<base>` 与覆盖层脚本——**不需要改你的构建配置**。

**做不到的**：
- 运行时才生成的内容（源码里搜不到）→ 明确报「定位不到」，**不会乱改别处**
- 纯动态样式（如 JS 计算出的渐变）→ 只能改静态声明
- 自由绝对定位（Figma 式拖到任意位置）→ 只在预览里生效；落盘必须是 CSS 语义
  （这是硬约束：能确定性写回源码，就不可能同时自由绝对定位）

## 安全与可回滚

**四道闸门，任何一道不过就整体拒绝改：**

1. **最小补丁**：只替换属性值那一段字符，其余字节不动
2. **配平校验**：引号 / 花括号 / 圆括号必须成对、行数不能变、体积不能异常膨胀
3. **冲突检测**：磁盘内容在编辑期间被外部改过 → 拒绝写入，让你先刷新（不覆盖你的修改）
4. **快照**：每次落盘前把被改文件的原文存到 `$DSH_HOME/visual-canvas/snapshots/`，撤销就是按快照还原

**只允许改「已存在元素的样式」**，不做结构重构（那是下一步的事）。
所有写操作都限在 `projectRoot` 之内（路径越界直接抛错）。

**访问控制**：覆盖层与代理都走 DSH 自己的回环信任链（`127.0.0.1` + Host 头 + same-origin 检查），
非回环来源 403，Host 不是回环地址直接拒绝（防 DNS 重绑定）。

## 已知限制

如实列出**没做**的部分（而不是含糊带过）：

- **A 档（编译期注入）没做**：目前靠 B 档（React fiber / Vue 实例 / Svelte 元数据）+ C 档（按文本/class 搜索）。
  React/Vue/Svelte 的 **dev 构建**通常够用；生产构建没有 `_debugSource`，会退到 C 档。
- **Tailwind class 写回没做**：`detectProject` 能识别出 Tailwind 项目，但写回统一走内联样式。
  工具类替换需要一张「值 ↔ 类名」映射表，那是 P2 的剩余项。
- **不做结构改动**：拖动只写 `transform`，缩放只写 `width`/`height`；
  不重排 JSX 结构、不增删元素、不改组件层级。
- **断点编辑没做**（手机/桌面切视口生成 media query）。
- **HMR 靠你自己的 dev server**：插件写完文件就结束，不做刷新。
- **快照不自动清理**：长期使用会在 `$DSH_HOME/visual-canvas/snapshots/` 积累，目前需手动清。
- **一个插件实例对应一个项目根**：要同时编辑多个项目就装多行（各用不同 `id` 与 `prefix`）。

```
│ lib/git.js      git 检查点（可选审计）            │

└──────────────────────────────────────────────────┘
```
